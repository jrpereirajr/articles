     ## Critical finding: spec vs. implementation

     The class doc comment is explicit: *"Back-to-back bookings (one ends exactly when the other starts) do NOT conflict."* The implementation uses `<=` on **both** sides, so exact endpoint touching returns **conflict**: 09:00–10:00 vs 10:00–11:00 → busy. The correct half-open form is `(s1 < e2) && (s2 < e1)`; the only case where the two differ is the exact-touch boundary — precisely the case the spec calls out.

     **Plan: encode the documented contract.** The two "meets" tests (predicate + integration) are expected to fail today — that's the red anchor of the TDD loop. Everything else characterizes current behavior.
